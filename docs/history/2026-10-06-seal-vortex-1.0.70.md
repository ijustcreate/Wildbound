# 1.0.70 — spiraling board seal and bounded finale rendering

## Request, cause and implementation

The end-of-expedition pull-in lagged and looked like straight shrinking rather than a particle warp. Preserve the existing uncommitted 1.0.67–1.0.69 game/UI work. Base remains `edc664ea35a4c75710570680dca26c6e1387f658`, `main` tracking `origin/main`; no commit or push requested.

The previous renderer cloned and moved the entire scenery array each sealing frame, transformed every enemy (including offscreen ones), re-sorted/re-rendered the world, and repeatedly invalidated tree bitmap caches by changing size/position. Terrain faded grey independently rather than following a swirl.

- `src/seal-vortex.mjs` adds a hue-preserving inverse-polar WebGL warp: inner terrain rotates faster than outer terrain, contracts into the board, and releases the room below. A fixed 112-mote pool supplies colored leaf/dust streaks, three curved wind ribbons, tilted portal rings, a restrained closure flash and a readable themed title. No runtime pixel readback or per-frame world/entity allocation.
- While a finisher holds the interaction, `Renderer.rememberSealScene` copies the already-rendered pre-HUD world to a bounded bitmap. Protected party/table silhouettes are replaced with cached floor art; they do not leave holes or duplicate heroes. The seal consumes this prepared frame without another scenery/rig pass. Restore/resizing/no prepared frame uses a one-time capture, not a repeated capture.
- Players, owned pets/ghosts and table stay in a separately cached layer. The camera stays steady during sealing. The visual projection does not move/damage game entities, change item ownership, or alter the existing victory reward rules.
- Scene, overlay and finale staging surfaces cap at 960×540; the finished stage is upscaled once to the normal high-DPI canvas. A single shader pass uses one texture upload per seal. GPU preparation occurs under the initial loading screen, and one tiny compiled context can be reused across expeditions/lobby renderer changes. Scene buffers/textures are released after the seal.
- A bounded 20-band Canvas approximation handles missing/lost WebGL. It keeps the same contraction, particles and portal, without the expensive clipped triangle mesh used in an intermediate implementation. No additional blur/glow, minimap, weather or cel-shading passes run during the warp.

## Verification and measurement limits

- Seven Node cases cover monotonic inward motion, differential rotation, bounded memory/particles/bands, no world traversal during sealing, warm-frame consumption, cold capture/resize/time reversal, no simulation mutation, seal save/reload, personal gear/chests and once-only shared victory rewards.
- `scripts/verify-seal-vortex.cjs` uses isolated Electron data. It stops only its own page's ordinary animation scheduling before the benchmark, uses real loaded artwork, compares 164 and 1,312 visible scenery entries, captures four visual stages, checks capture/upload counts, and exercises 600×430/1920×1080 surfaces, forced WebGL context loss, reward idempotency and buffer release. Its one-pixel readbacks are QA-only, to measure forced raster completion; they are not in the game.
- Source GPU check passed all behavior checks: median frame draw submission ~1.8 ms, p95 ~2.9 ms; median animation cadence ~16.7 ms with p95 ~33.3 ms. Forced-readback timings are much larger and must not be presented as ordinary gameplay FPS. The new software check measured ~16.4 ms median forced-raster cost for 164 entries and ~13.9 ms for 1,312; the previous packaged 1.0.69 software path measured ~887.7 ms and ~5,748.3 ms respectively in a shorter stress sample. Sampling, GPU scheduling and other running applications vary; these are isolated renderer diagnostics, not physical gameplay or a universal 60 FPS claim.
- Dense stress preparation still pays the existing normal-world render cost. The seal no longer repeats that cost, but this does not make all normal large-level rendering free. Cold restore/resize can still require one scene capture. The Canvas fallback is less visually continuous than the GPU warp. Known unrelated bundled full-game smoke failures from 1.0.68 remain; do not claim all-game smoke success.
- Final full Node run: **691/691 passing**. Syntax check: **196 runtime files**. Exact 1.0.70 ASAR checks pass for the GPU seal, explicit software/Canvas seal, `verify-inventory-workbench.cjs`, `verify-starter-chest.cjs` and `verify-tv-wildbound.cjs`. All **188 JavaScript runtime files** compared byte-for-byte with source; package metadata is intentionally pruned by the packager, with its version separately checked.
- Exact packaged GPU run: median draw submission **2.3 ms**, p95 **3.9 ms**; median/p95 offscreen cadence ~33.3/33.4 ms. Explicit packaged software fallback: median/p95 draw ~30.4/60.3 ms and cadence ~50.1/83.4 ms. Software rendering is improved over the previous expensive tree-cache churn, but is not guaranteed 60 FPS. The source/packaged cadence difference and forced-readback costs reinforce the limits above. Both backends passed real scene/resize/reward/buffer checks; the GPU run also passed deliberate context-loss fallback (its native GPU warning was expected).
