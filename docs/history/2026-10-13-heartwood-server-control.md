# Heartwood Passage and persistent server control panel

The developer field console now has a separate **Heartwood Passage (dev only)** action. It opens a permanent portal beside the selected explorer. Crossing moves the live party, their inventory, and board play to a fresh boundless forest clearing; the forest has a return portal beside its board. Each world's board and entities are captured when leaving and restored on re-entry. The normal event deck does not include this action. The journey is part of the expedition save.

The separate **Wildbound Server Control** window is launchable with `Server Control.cmd` or the local Desktop shortcut. It follows the existing Encore status window's shape: status, local/public health, authority/tunnel counts, connection address, copy button, uptime, players, last save, save, announcement, and safe stop. Closing the window hides it in the tray. It never connects to or controls the existing LAN room host.

The dedicated persistent gameplay server is not in this source tree yet. The panel deliberately shows offline until a future local server implements `127.0.0.1:4184` admin endpoints. The panel calls `GET /admin/status` and `POST /admin/save`, `/admin/announce`, `/admin/stop` with `x-wildbound-admin-token`. The status response should provide `uptimeSeconds`, `playerCount`, `players`, `worldSeed`, `lastSave`, `authorityCount`, `tunnelCount`, `localHealth`, `publicHealth`, and `publicAddress`. Only `publicHealth: true` displays public multiplayer as active. Keep the admin listener on loopback; the public game endpoint and tunnel are separate.
