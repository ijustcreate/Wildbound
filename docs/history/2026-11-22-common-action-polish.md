## Changes

- `src/save-coordinator.mjs` coalesces immutable snapshots behind one awaited drain, retains retryable errors and prevents an older successful write from clearing a newer capture failure. Runtime status stays outside serialized game state.
- `app.mjs` applies that queue to ordinary expedition and named world saves. The existing desktop close callback now flushes both expedition or world progress and character persistence. Save and return waits and keeps the active session open on failure. Pause actions have Save now or Retry, save status and safe recovery. Gameplay displays persistent save failure feedback. Lobby and controller-accessible lobby pause actions can continue an ordinary saved expedition.
- `src/profiles.mjs` returns the capture task and does not incorrectly deduplicate a return to the last committed state while a different profile write is active.
- `src/rooms.mjs` excludes the live train audio service from snapshots. Named world saving previously failed with a WeakMap DataCloneError after normal app wiring; real Electron save and restore now exercise that path.
- Settings participate in the existing controller neutral-release guard. Confirm and Back glyphs use the relevant physical face labels. Car and loot hints resolve the current player's mapping and family; loot hints explain capacity and do not promise hold to equip for stackable material weapons.
- `src/action-feedback.mjs` provides bounded, owned, merging pickup and refusal acknowledgments. Arrows and pickups report committed quantities, potions distinguish full health from missing supplies and report actual healing, and ammunition and mana failures have visible reasons. Toast placement scales with camera zoom to avoid covering the explorer's face.
- `src/combat-feedback.mjs` displays resolved enemy health loss, aggregates rapid repeated damage and caps simultaneous damage labels. Existing player health loss feedback is retained.
- `src/safe-recovery.mjs` validates nearby outdoor ground or private storage floor before moving only the selected explorer. It clears stale movement and sword state while retaining health, inventory, currency and carried-object identity. Pending held inventory transactions, active vehicles, controlled followers and custom underground rooms receive explicit refusals. A separate confirmed fallback uses the first stable position observed in the current context; it is not a persisted entrance checkpoint.
- World menu asynchronous actions preserve controls that were already disabled. A newly added loot progression Set iteration crash was corrected without changing the reward rules. An existing discrete-audio-event test now stubs the new unrelated procedural ambience methods so its lightweight AudioContext fixture remains appropriate to that test.
